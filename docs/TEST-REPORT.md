## 0.5.2 — no startup inventory of open tabs

- Cause: startRecorder enumerated the selected window's entire existing tab list and wrote one tab_snapshot/Initial page per HTTP(S) tab. This was an address inventory, not a visit. It did not call tabs.update to activate or reload tabs, but created unwanted history entries and disk writes.
- Start now queries only `{windowId, active:true}` and writes at most one initial HTTP(S) page. When the workspace tab is active it can use the already-displayed sourceTabId, validated against the same window/incognito/protocol rules. Future real activation of an existing page writes Tab visited, and actual navigation maintains the active-tab context. Other-window scope and immutable historical files remain unchanged.
- A strict regression also exposed a delayed pre-start navigation: asynchronous tabs.get resolved after Start and the old callback was adopted by the new session. Navigation/activation receipts now bind to the current session ID before asynchronous processing; no-recording receipts cannot join a later session. A worker-wake path waits for persisted session restoration, so the first waking navigation is not accidentally discarded. No wall-clock/cross-process timestamp comparison is used as an ingress gate.
- `npm run check`: ESLint, **17/17 unit tests**, clean build PASS. Final session E2E run **6/6 PASS**, including CFT and installed Chrome. Two startup regressions preload **eight background HTTP tabs**, then assert exactly session_started + one tab_snapshot, absence of background URL markers from recorded events/state, unchanged active tab and zero tab activation/loading notifications during Start. Explicitly activating one old tab records only that page as Tab visited, with no extra Initial page. Starting again from a foreground workspace tab records only its displayed same-window source.
- Existing one-window/moved-tab/case-pinning/panel-closure/export/tamper/window-close flow passes, including returning from a new linked tab. Failure/retry/Pause/browser-restart passes. Both native-FSA worker probes now explicitly call CDP ServiceWorker.stopAllWorkers and verify the first subsequent navigation is saved, then independently read/hash every event file. Native OS picker/permission UI and natural idle-timer termination remain distinct from this forced-worker-stop test.
- Final build/source/ZIP: **24/24 byte-identical files**, SHA-256 `0a3ebb3fc14c5de77f85305be1dcddb110c3de8f5419b4bd8371cb38d8ff28ab`. `git diff --check` PASS.
