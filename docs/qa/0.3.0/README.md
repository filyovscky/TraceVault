# Реальный QA 0.3.0

22.10.2026, Windows. PNG интерфейса: установленный Chrome 155.0.8059.85, реальный SIDE_PANEL + 32 сочетания light/dark × 320/360/420/520 CSS px × DPR 1/1.25/1.5/2. Протокол — native-layouts.json. Визуально просмотрены dark 360 и light 320/DPR2, знак 16/128, страница 1 и последняя страница PDF. Артефакты не являются дизайн-макетами.

Полный снимок проверен в CFT 156 и установленном Chrome 155 без эмуляции viewport. Тестовая страница 1500×2400 CSS px с горизонтальной/вертикальной прокруткой: проверены кадры, порядок, размеры, SHA-256 и цветные полосы на всём протяжении. Отдельно настоящий browser zoom 125%: 3000 строк цвета проверены без однопиксельных щелей.

[sample.pdf](sample.pdf) — производный PDF, созданный собственным JS расширения из реального полного PNG тестовой страницы. pypdf проверил структуру/число страниц/метаданные и побайтное совпадение всех распакованных RGB streams с PNG. PyMuPDF только отрендерил [первую](page-1.png) и [последнюю](page-2.png) страницы. Хеши/результаты — verification.json. Текст сайта в PDF — растровый; нижний колонтитул имеет Capture ID/номер страницы. OCR/HTML reflow/PDF-A не заявляются.

Повторение: `npx playwright test tests/rendering.e2e.mjs`, затем `python scripts/verify_pdf.py --render` (локально нужны Pillow, pypdf, PyMuPDF; в ZIP они отсутствуют). В конце E2E исходный PNG специально изменяется для проверки отказа, поэтому для независимого сравнения используется сохранённая тестом до подмены reference-full.png с исходным проверенным SHA-256.

Просмотр PDF по blob в Chrome реально не работал из-за CSP. Эта кнопка удалена, политика object-src none сохранена. Работают сохранение в выбранную папку, конвертация сохранённого PNG, проверка хешей, копирование относительного пути PDF и экспорт. Пользователь открывает PDF из папки внешним просмотрщиком.
