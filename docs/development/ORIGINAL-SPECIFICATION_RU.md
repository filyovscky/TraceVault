# TraceVault — полное техническое задание

**Версия спецификации:** 1.0 · **Дата:** 22 октября 2026 года  
**Статус:** задание для ИИ-разработчика, не утверждение о реализованном продукте  
**Продукт:** локальное расширение Google Chrome для фиксации цифровых материалов OSINT-расследований и подготовки данных для OSINTchart.  
**Язык интерфейса MVP:** русский; архитектура локализации должна допускать английский.  
**Основная ОС MVP:** Windows 11; Chrome Manifest V3; остальные Chromium-браузеры — после тестирования.  
**Ключевая установка:** local-first, offline-first для сохранённых материалов, управляемый пользователем доступ, никакого обязательного облака.

## 1. Суть и назначение

TraceVault — расширение Chrome, помогающее OSINT-аналитику и частному детективу фиксировать веб-страницы, скриншоты, фрагменты текста, собственные комментарии и выявленные сущности в заранее выбранной локальной рабочей папке. Каждый материал относится к конкретному расследованию и имеет постоянный идентификатор, точные временные метки, ссылки на источник, статус сохранения и контрольную сумму.

Ключевые свойства:

1. Одно действие для сохранения текущей страницы в **один автономный HTML-файл** (по принципу SingleFile).
2. Вся работа в заранее выбранной пользователем папке; никаких обязательных отдельных диалогов сохранения для каждого материала.
3. Везде точные и однозначно определённые время и дата, включая UTC и локальную временную зону.
4. Видимые выделения и заметки на живых сайтах, которые отображаются только при включённом расширении/режиме аннотаций и не модифицируют оригинальное содержимое сайта.
5. Создание Entity из выделенного текста и неизменяемая ссылка от Entity к исходному фрагменту и сохранённому файлу.
6. Подготовка нормализованных данных для последующего импорта в OSINTchart.
7. Полностью локальное хранилище; приватные данные не уходят на сервер продукта.

Типовые сценарии: исследование сайтов компаний, расследование мошеннических схем, проверка аккаунтов и публикаций, фиксация удаляемых материалов, построение хронологии обнаружений и привязка первоисточников к выводам. Продукт не предназначен для получения несанкционированного доступа к ресурсам.

## 2. Границы и сознательные исключения

**Запрещено добавлять без нового решения заказчика:** «Проверить в других источниках», собственный OSINT-поисковик, набор автоматических запросов к третьим сервисам, принудительную облачную синхронизацию, рекламу, телеметрию по умолчанию, автоматическое объявление найденных совпадений доказанными фактами, незаметное сохранение всех просмотренных страниц по умолчанию.

**Не обещать:** побайтово точную копию исходного ответа HTTP, идеальную работу с любыми SPA/canvas/video/DRM страницами, захват всех кросс-доменных iframe, юридическую допустимость в суде одной лишь программной функцией, достоверную фиксацию времени только по часам компьютера.

## 3. Роли и объекты предметной области

- **Workspace:** корневая рабочая область в выбранной локальной директории. Может включать несколько расследований.
- **Case:** дело/расследование с уникальным UUID, кодом, названием, описанием и настройками.
- **Source:** первоисточник: URL, сайт, конкретная версия страницы, источник файла. Сохранять исходный и конечный адрес, не путать веб-адрес с объектом-доказательством.
- **Capture:** событие фиксации страницы или другого содержимого, привязанное к делу и времени.
- **Artifact:** фактически записанный на диск файл, например HTML, PNG, исходный PDF. Имеет хеш, размер и путь.
- **Annotation:** выделение, маркер, комментарий, привязанный к URL, версии страницы и фрагменту содержимого.
- **Evidence Reference:** неизменяемая ссылка из заметки, Entity или вывода на Capture/Artifact/фрагмент.
- **Entity Draft:** выявленная вручную сущность или кандидат на сущность с типом, значением, доказательством и статусом проверки.
- **Activity/Audit Event:** записанное событие работы с данными.

Разделяй концепции **«источник»**, **«зафиксированная копия»**, **«найденный факт/утверждение»** и **«аналитическая гипотеза»**.

## 4. Главный UX-поток

### 4.1 Первый запуск (P0)

1. Открыть расширение → небольшая приветственная страница.
2. Нажать **«Выбрать папку рабочей области»** → системный выбор директории (`showDirectoryPicker` в документе расширения).
3. Запросить разрешение чтения/записи; создать служебную структуру только в выбранной директории.
4. Создать первое дело или открыть найденное в папке.
5. Назначить активное дело.
6. Предложить, но не навязывать, быстрые клавиши и включение аннотаций.
7. После завершения — рабочая боковая панель.

Нельзя считать настройку завершённой, если доступ к папке не проверен тестовой операцией, выполненной корректно и без перезаписи пользовательских данных.

### 4.2 Сохранение страницы (P0)

На странице пользователь нажимает **«Сохранить страницу»** или горячую клавишу. Расширение:

1. Определяет активную вкладку и активное дело.
2. Сразу регистрирует событие начала фиксации и присваивает `capture_id`.
3. Считывает URL, заголовок, сведения о вкладке, время и технические параметры.
4. Формирует автономный HTML, встраивая доступные стили, картинки, шрифты и другие необходимые ресурсы.
5. Записывает **ровно один HTML-файл на одну фиксацию страницы** в папку дела; никакого каталога из HTML и сотни ресурсов рядом.
6. Вычисляет SHA-256 именно окончательно записанного файла.
7. Сохраняет запись в индексе и журнале дела.
8. Показывает честный итог: `Сохранено`, `Частично сохранено` или `Ошибка`, с размером, временем и кнопкой «Открыть файл».

**Важное уточнение:** один HTML-файл — требование к **архиву веб-страницы**. В рабочей папке отдельно допустимы скриншот PNG, файл журнала, индекс и файлы экспорта — это разные типы материалов. Никаких `index.html + assets/` для одного архива. Создавать папку под каждую страницу по умолчанию не нужно.

Не путать сохранение текущей страницы с загрузкой исходного HTML сетевым запросом: нужно пытаться воспроизвести именно видимое пользовательское состояние DOM, включая раскрытые блоки, если они представлены в документе в момент фиксации.

### 4.3 Сохранение выделенного текста (P0)

Выделить текст → контекстное меню или компактный tooltip → `Сохранить фрагмент`, `Выделить`, `Создать Entity`, `Заметка`. Сохранять точную цитату, surrounding context, адрес, дату и доступные якоря. Если страница не была архивирована, предложить фоновое/явное сохранение страницы в рамках разрешённой операции либо пометить ссылку `live_only`. Не заявлять, что источник зафиксирован, если имеется только URL и цитата.

### 4.4 Повторный визит (P0)

Когда пользователь вновь открывает URL, система ищет существующие заметки, аннотации и факты по активному делу. При включённом режиме подсветки аккуратно восстанавливает сохранённые выделения. История захватов доступна в панели. Повторное сохранение **создаёт новую версию Capture**, не переписывает старую.

### 4.5 Переключение расследований (P0)

Активное дело всегда очевидно. При переключении меняются список материалов, режим аннотаций и destination для новых записей. Переключение не должно менять уже сохранённые документы. Не допускай случайного сохранения в прежнее дело при долгой асинхронной обработке: capture получает `case_id` в момент старта, он не изменяется при последующих переключениях.

## 5. Формат архивирования — SingleFile-подобный HTML

### 5.1 Обязательные требования (P0)

- Экспорт в стандартный файл `.html`; работа офлайн в обычном Chrome без TraceVault.
- Все доступные необходимые ресурсы, включая CSS, изображения и шрифты, должны быть инлайновыми (data URI, встроенные блоки или аналогичный одноконтейнерный механизм).
- Поддержать UTF-8, кириллицу, Unicode, CSS background images, SVG, относительные ссылки, `srcset` и типичные iframe — при доступности ресурсов и разрешений.
- Пытаться сохранить текущее пользовательское состояние формируемого DOM без внесённых TraceVault оверлеев.
- Не добавлять служебные аннотации пользователя как часть оригинала: они лежат отдельно, поверх него.
- Не требовать открытого сетевого соединения для просмотра сохранённой страницы; отдельно выявлять и сигнализировать ресурсы, которые всё же обращаются в сеть или не были встроены.
- Воссоздание — **best effort**, а не гарантированная пиксельная или байтовая идентичность.
- Повторная версия сохраняется отдельным файлом, даже если URL идентичен.
- По возможности исключить активный скрипт или сетевые обращения при просмотре архива; описать модель безопасного чтения потенциально враждебного HTML.

### 5.2 Источник движка

Проанализировать официальные исходники SingleFile и SingleFile MV3, их API, известные ограничения и **лицензию AGPL-3.0**. Варианты: независимый движок с аналогичным пользовательским результатом, правомерно лицензированное использование соответствующих частей, отдельная явно лицензированная библиотека. **Не копировать код SingleFile в закрытый продукт без проверки совместимости лицензии.** Ссылка: https://github.com/gildas-lormeau/SingleFile .

### 5.3 Расширенная диагностика захвата (P1)

Список неполных ресурсов: URL, тип, причина отказа, статус загрузки, CORS/permissions ограничения, размер, timeout. Сохранять полный перечень в машинно-читаемой записи; UI показывает понятное summary. Особые случаи: iframe другого происхождения, lazy loading, виртуальные списки, shadow DOM, canvas, video, WebGL, сайты с авторизацией, контент за скроллом, CSP, большие страницы, перенаправления, неподдерживаемые Chrome страницы. Не делать неконтролируемую автоматическую прокрутку, если она может изменять сайт или раскрывать дополнительные данные; использовать явный режим `Подгрузить всю страницу`, описывающий вмешательство.

### 5.4 Опции (P1)

- Сохранение только выбранной области/DOM-фрагмента в автономный HTML.
- Отчёт о сетевых зависимостях итогового HTML.
- Сравнение двух сохранённых версий: текстовое diff, структурное diff, визуальное diff со статусом достоверности.
- Гибкие профили захвата по доменам при явном согласии пользователя.

## 6. Скриншоты и другие артефакты

**P0:** скриншот видимой области (`chrome.tabs.captureVisibleTab`) с сохранением PNG без искажений, исходные пиксельные размеры, масштаб страницы, `devicePixelRatio`, размер viewport, URL, время. Оверлей TraceVault перед снимком должен быть скрыт по понятному правилу: режим `чистый снимок` по умолчанию, `с пометками` — только отдельная производная копия с явным обозначением. Пользователь не должен терять аннотации после временного скрытия.

**P1:** полный скриншот длинной страницы, склейка нескольких кадров, фиксация порядка кадров и метаданных о скролле. Динамические sticky элементы могут дублироваться — диагностировать и не обещать универсально идеальный результат. Инструмент захвата прямоугольного фрагмента, сохранение выделенного изображения без повторной JPEG-компрессии, если доступен оригинальный файл.

**P2:** видеозапись выбранной вкладки с явным стартом/стопом через `tabCapture`/MediaRecorder. Фиксировать временные метки и ограничения; не заявлять запись событий с точностью лучше фактической. Не включать в MVP, чтобы не отвлекать от сохранения HTML.

## 7. Точное время фиксации — критический модуль (P0)

### 7.1 Обязательные типы времени

- `capture_started_at`: начало процесса фиксации.
- `capture_finished_at`: момент завершения получения данных.
- `artifact_write_started_at` и `artifact_written_at`: запись окончательного файла.
- `record_created_at`: создание записи в индексе.
- `first_seen_at`: первое обнаружение адреса в рамках дела, если наблюдалось.
- `annotation_created_at`, `annotation_updated_at`: создание и правка заметки.
- `entity_created_at`: создание локального Entity draft, не дата создания самого объекта в мире.
- `source_published_at`: **только** заявленная сайтом дата публикации; никогда не отождествлять с временем фиксации.
- `timestamp_token_issued_at`: только при успешной внешней доверенной метке времени.

### 7.2 Формат

- Машинное хранение: ISO 8601/RFC 3339 с явной зоной и миллисекундами; UTC `2026-10-22T11:42:17.384Z`.
- Для пользовательского интерфейса: локальное `22.10.2026 14:42:17.384 (UTC+03:00)`; UTC доступен рядом или по наведению.
- Хранить `timezone_id` (`Europe/Moscow` или другая IANA зона, известная браузеру), `local_offset_minutes`, `clock_source` (`system_clock`, `trusted_timestamp`), необязательное поле оценки погрешности и статус синхронизации, если он определён.
- Время не создавать вручную в UI по догадке и не преобразовывать в строку без зоны.
- Нельзя иметь голые `сегодня в 12:30` без полной даты в карточке доказательства, экспортированном файле и журнале.
- Учитывать смену часового пояса и DST: UTC первичен, исходную локальную зону фиксировать в момент события.
- Измерение продолжительности операции отделить от настенных часов и вычислять по монотонному времени, когда доступно.

### 7.3 Уровень доверия

**Локальное системное время не является независимым подтверждением момента фиксации.** Хранить это явно. P1: опциональная синхронизация или контроль расхождения времени; P2: доверенные серверные timestamp tokens по RFC 3161 для SHA-256, с явной сетевой передачей только хеша и согласием пользователя. Не утверждать `судебно подтверждено` без отдельной процедуры. При сбое часов сохранять событие о возможной недостоверности времени.

## 8. Выбранная папка — главная гарантия хранения (P0)

### 8.1 Принцип

Пользователь явно выбирает **корневую папку Workspace**. Все данные пишутся в неё, в предусмотренные подпапки дел, без дополнительного `Save As` на каждый захват. UI всегда показывает название и состояние выбранной папки. Пользователь может указать новую директорию, переместить рабочую область и повторно подключить существующую.

**Недопустимо:** тайком переключаться на Downloads, сохранять только в IndexedDB и утверждать, что файл оказался на диске, выбирать папку без пользовательского жеста или обходить разрешения Chrome.

### 8.2 Реализация

- Из обычного документа расширения (панель или options, не service worker) вызывать `window.showDirectoryPicker({mode:'readwrite'})` только по клику.
- Сохранять `FileSystemDirectoryHandle` в IndexedDB там, где это поддерживается; на запуске проверять `queryPermission`, при необходимости по действию пользователя — `requestPermission`.
- Проверять доступность папки: её могли удалить, переименовать, переместить, заблокировать политикой безопасности либо доступ мог быть отозван.
- Когда запись запрещена: чётко показывать `Требуется повторный доступ к папке`; ставить операцию в ограниченную очередь/черновик, **не подтверждать успех**, не сохранять в другое место молча. Черновики в браузерном хранилище — временные, не первичный источник истины.
- Должны быть обработаны `QuotaExceeded`, нехватка диска, `NotAllowedError`, отмена выбора, permission revoked, ошибка записи, аварийное завершение Chrome.
- Сопровождать каждый захват проверкой открытия/чтения итогового файла и хеша после записи для критичного режима.
- Обновления каталога делать crash-safe: сначала материал, затем проверка и подтверждённая запись в индекс; неполные захваты восстанавливать при повторном запуске.

`chrome.downloads.download` **не является** основным решением, потому что принимает путь относительно системной папки Downloads, а не произвольную выбранную пользователем абсолютную директорию.

Путь в индексе только относительный к корню workspace/дела, не абсолютный; это обеспечивает переносимость между ПК. Нельзя использовать путь или URL напрямую в имени без санитизации. Ограничить длину имени и обработать коллизии через ID. Если пользователь указывает непосредственно папку дела, предусмотреть режим `одна рабочая папка = одно дело` без лишнего уровня вложенности.

### 8.4 Гарантии

- Хранить данные в читаемых открытых форматах; никакой зависимости от существования расширения для открытия HTML и PNG.
- При переоткрытии существующего Workspace восстановить индекс дел, аннотации и связи без потерь.
- При изменении структуры — миграция с резервным снимком и проверкой.
- Удаление через UI не должно мгновенно и необратимо уничтожать исходники: корзина и аудит (P1).
- Хеш считается по сохранённым **байтам**, а не только по исходной JS-строке до записи.

## 9. Метаданные, целостность, аудит (P0)

### 9.1 Capture

Каждый захват имеет UUID, человекочитаемый номер `EVD-000037` в рамках дела, тип, источник, точные времена, размеры, версию расширения и Chrome, статус полноты, ссылки на артефакты, диагностический отчёт и ссылку на предыдущую версию страницы, если есть.

### 9.2 Артефакты

Артефакт: `artifact_id`, `capture_id`, `kind`, `relative_path`, `mime_type`, `byte_length`, `sha256`, `created_at`, `written_at`, `verification_status`. Для других криптографических алгоритмов потребность решать отдельно; MD5 не использовать как единственный признак целостности.

### 9.3 Аудит

Регистрировать: создание дела, смену активного дела, старт/завершение/провал захвата, успешную запись, создание/изменение аннотации, создание/изменение Entity draft, экспорт, импорт, проверку хеша, исправление метаданных, восстановление доступа, удаление/восстановление файлов. События append-only на уровне приложения; обычный JSONL не является криптографически неизменяемым. P1 — связывание записей журнала хешами и подписи манифестов для обнаружения вмешательств; не заявлять абсолютную защиту от локального злоумышленника.

### 9.4 Производные объекты

Оригинальный HTML и оригинальный PNG никогда не модифицируются при редактировании заметок или выделений. Все редакторские изменения живут в отдельных JSON-записях, версиях или файлах-аннотациях. Обрезанные/закрашенные скриншоты — отдельные файлы `derived_from`, с описанием преобразования. Удалённый первоисточник нельзя «заменить» ретушированной версией.

## 10. Аннотации на живых страницах (P0)

### 10.1 Ожидаемая механика

Пользователь выделяет текст на сайте → `Подсветить` → выбирает цвет (спокойная палитра), при желании пишет комментарий. В текущем DOM появляется неблокирующая подсветка. Пользователь отключает режим аннотаций → подсветки исчезают полностью. Включает снова → подсветки появляются. Отключает само расширение в Chrome → его вставленный UI исчезает после выгрузки/обновления вкладки; при повторном включении/перезагрузке подсветка восстанавливается из локального хранилища, когда механизм инъекции снова работает.

**Важно:** не обещать, что Chrome мгновенно удалит уже вставленные DOM-узлы при отключении расширения на открытой вкладке без перезагрузки. Для собственной кнопки `Показывать аннотации` удаление оверлея должно происходить немедленно. Для отключения расширения целиком корректность после обновления страницы является обязательной.

### 10.2 Не менять сайт

- Подсветки реализованы content script (overlay/CSS Highlight API при проверенной совместимости или минимальная безопасная инъекция); DOM сайта не должен повреждаться.
- Не удалять и не заменять текстовые узлы сайта как основную технику, если она разрушает обработчики/выделения/доступность.
- Размещать элементы так, чтобы не ломать прокрутку, клики, формы, sticky UI, CSS и z-index.
- В начале SingleFile-захвата временно выключать визуальные элементы TraceVault либо исключать их из сериализации. В конце гарантированно восстанавливать состояние независимо от результата операции.
- Не сохранять на сайте ничего через POST/PUT; аннотации существуют только локально.

### 10.3 Устойчивые якоря для выделений

На одну аннотацию хранить несколько координат:

1. Исходный URL и `capture_id` соответствующей версии (если имеется).
2. `TextQuoteSelector`: `exact`, ограниченные `prefix`/`suffix`.
3. `TextPositionSelector`: смещения в согласованной нормализованной модели текста.
4. DOM Range/path или CSS/XPath-подсказки для быстрого восстановления, не как единственный источник истины.
5. Для изображений/визуальных областей — геометрический якорь с размерами viewport, DPR и идентифицируемым DOM-элементом.

Алгоритм восстановления: строгий поиск по селектору → проверка окружающего контекста → единственное совпадение → отображение. При нескольких совпадениях: маркировка `ambiguous`, предложение выбрать. При отсутствии: `orphaned`, показ текста в боковой панели без ложной подсветки. При существенных изменениях страницы не переносить маркеры на случайные похожие слова.

### 10.4 Операции

Создать, выбрать, изменить цвет, добавить заметку, изменить заметку, удалить/скрыть, фильтровать по делу и тегу, перейти к выделению, экспортировать. Хранить автора, точное время создания и правки, версию якоря, статус восстановления, цитату, связанный Evidence Reference, связанные Entity IDs. Для длинных материалов — список всех выделений в правой панели с переходом к месту.

### 10.5 Особые страницы

Динамические SPA, перестройка DOM, виртуализированный контент, iframe, shadow DOM, одинаковые цитаты, бесконечный скролл. Применять throttled MutationObserver и обоснованный предел вычислений; не выполнять полное сканирование страницы на каждую мутацию. Поддерживать частичный успех с видимой диагностикой.

## 11. Заметки и цитаты (P0)

- Простой компактный редактор заметки с Markdown/WYSIWYG-подобным отображением в рамках карточки, без тяжёлого отдельного окна.
- Каждая заметка связана с делом, по желанию — с Capture, аннотацией, Source и Entity draft.
- Наличие редактируемой заметки **не меняет оригинальный архив**.
- Возможность создать заметку из текста выделения, из материала или вручную.
- В списке заметок показывать даты до секунд и доступ к полным временным полям.
- Быстрый поиск по заметкам и цитатам — P0; полнотекстовый поиск по HTML-архивам — P1.

## 12. Создание Entity и связь с источником — проектировать отдельно, реализовывать поэтапно

### 12.1 Целевой сценарий

Пользователь читает страницу о компании и выделяет `Иван Иванов`. Нажимает `Создать Entity` → тип `Person` → при необходимости правит имя → выбирает `Сохранить в дело`. Система создаёт **Entity draft** с постоянным UUID и отдельную **Evidence Reference**: указывает на `capture_id`, `artifact_id`, URL, точную цитату, якорь, время фиксации и статус проверки. Если HTML архив ещё не сделан, интерфейс должен ясно показать: `Связан только с живой страницей; доказательственная копия отсутствует` и предложить зафиксировать её.

После появления нескольких Entity на той же странице их источник **не копируется заново**: используются ссылки на один Capture и разные якоря. При повторной фиксации URL все ранее сформированные ссылки продолжают вести к версии, в которой цитата была обнаружена, а не «на самый новый файл».

### 12.2 Типы сущностей MVP

`person`, `organization`, `phone`, `email`, `domain`, `ip_address`, `url`, `username`, `location`, `document`, `file`, `hash`, `custom`. Каталог расширяемый. Не создавать жёсткий параллельный справочник несовместимых сущностей: использовать отображение на известные типы OSINTchart.

### 12.3 Нормализация и дедупликация

- Хранить **оригинальную строку** и отдельное **нормализованное значение**.
- Телефоны: нормализация по региону только при достаточном контексте; не угадывать страну из локали пользователя.
- Email: аккуратная нормализация доменной части; не уничтожать значимые особенности локальной части без правила.
- Домены: нормализация регистра и IDNA для сопоставления, исходное написание сохранить.
- URL: оригинальный URL и отдельный канонический ключ; удаление параметров отслеживания не должно нарушить доказательственную ссылку.
- Имена людей: совпадение строк не доказывает идентичность.
- При создании кандидата предлагать `Создать новый`, `Связать с существующим`, `Оставить неразрешённым`.
- Сливать сущности **только по подтверждению**, сохранять все доказательственные ссылки и журнал операции.

### 12.4 Атрибуция

Точно разделять:

1. **В тексте упомянуто** — объективно наблюдаемая связь `mentions`.
2. **На странице указано, что принадлежит** — утверждение источника `source_claims`.
3. **Аналитик предполагает связь** — гипотеза `analyst_inference`.
4. **Проверено независимо** — отдельный статус верификации с подтверждающими ссылками.

Выделение рядом с человеком телефона не означает доказанную принадлежность. Нельзя автоматически создавать графовую связь `owns` или `employed_by` только из совместного появления на странице.

### 12.5 Двухуровневая модель привязки

**Уровень A — Evidence Reference (основной):** Entity хранит ссылку на конкретный источник/фрагмент, без лишней Entity «веб-страница» на канвасе.  
**Уровень B — Source Entity (по желанию):** при включённой опции исследователь добавляет в граф явную Entity типа `document`/`url`, соединённую семантическим `mentioned_in` / `sourced_from` (или корректно согласованным в OSINTchart ключом). Этот режим не включён по умолчанию во избежание засорения схемы узлами каждого сайта.

### 12.6 Перспективная карточка Entity в расширении

Поля: тип, название/label, первоначально выделенная цитата, нормализованное значение, проверка дублей, список источников, статус достоверности (`unconfirmed` по умолчанию), комментарий, дата и время создания, возможность `Отправить в OSINTchart`. На карточке источник доступен как `Открыть сохранённый HTML`, `Перейти к фрагменту`, `Открыть оригинальный URL` — это разные действия.

## 13. Контракт с реальным OSINTchart

По состоянию на проверку репозитория `filyovscky/osintchart` 22.10.2026 приложение реализовано на Python/PySide6. В `src/osint_notebook/models/types.py` есть `GraphEntity`, `GraphRelation`, `EvidenceMeta`, `CustodyRecord`, `InvestigationCase`. У `EvidenceMeta` уже есть `source_url`, `acquired_at`, `evidence_refs`, `integrity_hashes` и `verification`; у Entity — `attributes`, `meta`, `custody_history`. В `docs/ENTITY_LIBRARIES_AND_EVIDENCE.md` указано, что интеграция богатых source refs — следующий шаг, а имеющаяся запись хеша пока **не рассчитывает и не проверяет** digest. Реализуй собственную проверку оригиналов в TraceVault, не приписывай OSINTchart несуществующие возможности.

**P0 — безопасный обменный формат, а не редактирование бинарных/внутренних файлов дел:**

- Версионированный `tracevault-osintchart-export.json` с `schema_version`, ID дела, массивами `entities`, `evidence`, `relations`, `annotations`, `artifacts`.
- Привязка Entity к Evidence Reference отдельным массивом или полем `evidence_refs`.
- В `GraphEntity.meta` у импортёра OSINTchart можно использовать `source_url`, `acquired_at`, `evidence_refs`, `integrity_hashes`, но не пытаться запихнуть всю модель Capture в строку URL.
- В `attributes` при подтверждённом соответствии шаблону можно передавать `entity_template_key` без произвольного изменения Enum `EntityType`.
- Если создаются отношения, учитывать действующий `relation_semantic_key` в атрибутах `GraphRelation`; не подменять утверждение доказанным отношением.
- Импорт в OSINTchart должен выполняться **через отдельный адаптер** и доступные сервисные методы; не переписывать `.oscase`, `.oscase.enc`, `.osint` без анализа форматов, миграций и проверок.
- Проверять существование ID на стороне целевого дела; импорт идемпотентный. Повторная отправка одной Entity не порождает дубликаты, но может добавлять новые ссылки на источники.
- Импорт должен быть предварительно просматриваемым: `Создать N`, `Обновить M`, `Конфликт K`, `Пропустить J`, затем явное подтверждение.

**P1 — прямое соединение:** через Chrome Native Messaging и маленький локальный companion на Python либо явный локальный HTTP-сервер с одноразовой привязкой и защитой от чужих сайтов. Для Native Messaging native host устанавливается пользователем, работает с фиксированным ID разрешённого расширения и передаёт JSON-сообщения. **Не выставлять незащищённый локальный HTTP API**, в который может записывать любой сайт. Очередь подтверждённых импортов, обработка отсутствия запущенного OSINTchart, ACK, retry, idempotency key, аудит. Никакого скрытого копирования всех материалов в OSINTchart без пользовательского действия.

**P2:** двусторонняя навигация: щелчок на Entity в OSINTchart открывает Evidence Reference и нужную локальную версию архива, щелчок на Entity в TraceVault выделяет соответствующую карточку на схеме. Перенос аннотаций, статус проверки, примечания к связям, конфликт-резолюция, связь с текущим открытым делом.

## 15. Пользовательские интерфейсы

### 15.1 Chrome Side Panel — основной интерфейс (P0)

Верх: логотип и название, селектор активного дела, заметное состояние доступа к папке, переключатель аннотаций. Затем: текущая страница (favicon, заголовок, адрес, существующие фиксации), одна первичная кнопка `Сохранить страницу`, компактные вторичные действия `Скриншот`, `Выделить`, `Заметка`, `Entity`. Ниже вкладки `Материалы`, `Аннотации`, `Сущности`, `История` либо один унифицированный список с фильтрами — выбрать по прототипным тестам. Низ: короткий индикатор фоновых операций и кнопка настроек. Нельзя заполнять половину боковой панели декоративными hero-элементами.

### 15.2 Полная рабочая область (P0/P1)

Открывается отдельной extension page/вкладкой: дерево дел, список материалов, просмотр архивов/скриншотов, полнотекстовый поиск по метаданным, панель источников, заметки/Entity drafts, история. Для MVP достаточно организации и просмотра материалов с фильтрами; сложный граф остаётся в OSINTchart. Имена и пути не должны обрезаться без tooltip/копирования. Быстрое переключение между делами.

### 15.3 Встроенные элементы сайта (P0)

Компактная панель при выделении текста (`Подсветить`, `Сохранить цитату`, `Entity`), не перекрывает выделение и не появляться в полях паролей, банковских формах и редактируемых элементах без отдельного действия. Лёгкие highlights, без постоянных больших плавающих кнопок. Можно скрыть все инъекции на текущем сайте и глобально.

### 15.4 Карточка доказательства (P0)

Номер, название, URL, время фиксации до миллисекунд, статус, размер, SHA-256, метод захвата, длительность, вложения, ссылки на цитаты и Entity, просмотр исходного HTML, `Проверить хеш`, `Показать на диске` (в пределах поддерживаемых возможностей), `Экспортировать`. Полный digest копируемый. Для невозможных host actions не рисовать активную кнопку без реализации.

### 15.5 Дизайн

Строгий профессиональный Obsidian-подобный плотный интерфейс: нейтральная палитра, один спокойный акцент, светлая и тёмная темы, одинаковая смысловая семантика цветов, аккуратные векторные иконки (не текстовые `x`, `>`, `...` вместо иконок), чёткий шрифт под Windows, выверенные отступы и скругления, без жирных градиентов, шаблонного SaaS-«нейрослопа», больших бесполезных карточек. Понятные hover/focus/active/disabled состояния, keyboard navigation, ARIA, локализация. Проверка размеров панели 320/360/420/520 px, масштабов Windows 100/125/150/200 %, длинных URL, кириллицы и тёмной темы.

## 16. Меню команд и горячие клавиши

Обязательные контекстные действия (P0):

- `Сохранить выделенный текст`;
- `Подсветить выделение`;
- `Создать Entity из выделения`;
- `Добавить заметку к выделению`;
- `Сохранить изображение` — только если доступно без обхода защиты и с сохранением источника.

Для MVP горячие клавиши: сохранить страницу, сделать скриншот, открыть/закрыть панель и добавить выделение. Конкретные сочетания должны учитывать конфликты с Chrome/Windows, а пользователь должен иметь возможность назначить их через стандартный механизм расширений Chrome. Не захватывать ввод глобально в input/textarea.

## 17. Управление разрешениями и приватностью

Минимальный набор permissions на каждую функцию. `activeTab`/`scripting` для явных действий; дополнительные host permissions запросить по необходимости для автоматического восстановления аннотаций на соответствующих доменах. `sidePanel`, `contextMenus`, `storage`, возможно `tabs`/`webNavigation` по обоснованию. Разрешения повышенной чувствительности (`debugger`, `<all_urls>`, `tabCapture`, `nativeMessaging`) не добавлять просто «на будущее»; использовать только для реализованных функций и документировать почему.

Не сохранять пароли и поля ввода с секретами как отдельные события; при архивировании авторизованной страницы предупредить, что её видимый текст и элементы интерфейса могут содержать личную информацию. Не собирать cookie, авторизационные заголовки, access tokens, HTTP bodies и историю всех вкладок по умолчанию. Чувствительные домены/инкогнито — исключены по умолчанию; для инкогнито поведение зависит от настроек разрешений Chrome и должно быть отдельным явным режимом. Не выполнять сетевые запросы к доменам пользователя ради аналитики на стороне сервиса.

Предусмотреть `Pause all capture`, чёрный список доменов, приватный режим работы, ясный экран `Какие данные хранятся и где`. P1 — шифрование workspace с понятным процессом разблокировки и резервного копирования; не выдавать простую обфускацию за шифрование.

## 18. Программная архитектура Chrome Manifest V3

Рекомендуемые границы ответственности:

- **Side Panel UI:** состояние интерфейса, действия пользователя, выбор каталога, просмотры.
- **Options / Workspace page:** управление делами, миграции, поиск, настройки.
- **Service Worker:** маршрутизация сообщений/событий, восстановление состояний, chrome APIs; **без долговременного хранения единственного экземпляра состояния в памяти**.
- **Content Script:** выделение текста, якоря, наложение highlights, локальная UI-панель, чтение разрешённого DOM.
- **Capture Engine:** сбор автономного HTML с явной диагностикой ресурсов.
- **Storage Adapter:** IndexedDB handle, файловые операции, транзакционный протокол сохранения, проверка хеша.
- **Index Repository:** журнал/метаданные, версионирование, восстановление после crash.
- **Evidence & Entity Service:** EvidenceRefs, дедупликация, нормализация, экспорт.
- **Export Adapter:** JSON для OSINTchart, проверка контрактов и версий.
- **Optional Native Companion:** только на отдельном этапе для локальной интеграции.

MV3 service worker может завершаться/перезапускаться; операции, требующие DOM и длительного исполнения, распределять через extension pages/offscreen document с корректными ограничениями Chrome. Offscreen document не является универсальной заменой service worker, он поддерживает ограниченный набор extension APIs. Нельзя строить сохранение на неограниченно живущем глобальном объекте JS.

### 18.1 Очередь сохранений

Состояния: `queued` → `capturing` → `writing` → `verifying` → `completed` / `partial` / `failed` / `cancelled`. У каждой операции UUID/idempotency key, captured `case_id`, зафиксированный URL, временные метки, прогресс, ограничения, причина сбоя. После перезапуска программа определяет зависшие операции, проверяет частичные файлы и предлагает повторить. Исключить тихую потерю задач и двойные записи при повторной доставке событий.

### 18.2 Конкурентность

При сохранении нескольких вкладок не смешивать контент, статус, URL, `capture_id` и активное дело. На один файл только один writer. Сериализация записи служебного журнала; согласованность при параллельных командах `Сохранить` и `Создать Entity`. Дедупликация «идентичная операция в коротком окне» по idempotency key, но **осознанная повторная фиксация** должна быть новой версией даже при одинаковом SHA.

### 18.3 Отображение локального архива

Не предполагать, что расширение может автоматически читать любые `file://` адреса. Для внутреннего просмотра открывать Blob/HTML из разрешённого FileSystemHandle с безопасной политикой sandbox/CSP или давать `Открыть файл` через доступный механизм. HTML из интернета потенциально содержит вредоносный скрипт и удалённые обращения; изоляцию просмотрщика и выключение опасных API продумать отдельно. При сомнении — открыть сохранённый HTML обычным браузером по явному действию пользователя и предупредить о рисках.

## 19. Производительность и устойчивость

- Сохранение небольших страниц не должно замораживать UI.
- Показ прогресса для больших материалов и явная возможность отмены.
- Обработка огромных HTML, десятков изображений, дублирующихся URL, нестабильной сети, медленного диска и нехватки места.
- Хранить большие Blob в памяти как можно меньше времени; избегать многократного сериализованного копирования.
- Механизм восстановления после Chrome crash, переключения вкладок и рестарта service worker.
- Ограничение максимального размера операции должно настраиваться; превышение → контролируемая ошибка/частичная фиксация, а не silent truncation.
- UI не должен зависеть от числа сохранённых файлов; для тысяч captures использовать постраничные списки и индексирование.

## 20. Поиск, фильтры и версии

P0: поиск по заголовкам, URL, цитатам, заметкам, меткам, Entity drafts, номерам доказательств; фильтры по делу, типу, дате, домену, статусу. Сортировка по точному времени, пользовательские закрепления. P1: полнотекстовый поиск по содержимому HTML без обращения в сеть; сравнение версий, поиск по OCR скриншотов, timeline с различением даты публикации и времени фиксации. P2: локальный семантический поиск, только по желанию пользователя и с документированием модели.

## 21. Отчёты и экспорт

**P0:** экспорт отдельных оригиналов, списка доказательств и машинного JSON для OSINTchart. JSON содержит относительные пути, а не только локальные file:// ссылки. Результат совместим с переносом всей папки дела между машинами.

**P1:** отчёт Markdown/PDF/DOCX: название дела, дата формирования отчёта (это не дата фиксации!), содержание, перечень зафиксированных материалов, URL, полные временные метки, хеши, изображения и выбранные цитаты с источниками. Приложения с копиями первоисточников в ZIP по явному выбору. Добавлять в отчёт **только** отмеченные материалы, чтобы не раскрыть посторонние чувствительные данные. При экспорте производных материалов указывать, какие элементы редактировались.

## 22. Состояния и ошибки UI

Обязательно предусмотреть отдельные экраны/сообщения для:

1. Папка ещё не выбрана.
2. Папка выбрана, но доступ отозван.
3. Сайт относится к запрещённым/неподдерживаемым страницам браузера.
4. HTML сохранён не полностью.
5. Сохранение успешно, но контрольная сумма не подтверждена повторным чтением.
6. Источник изменился, аннотация не восстановилась.
7. Найдено два одинаковых текста, якорь неоднозначен.
8. Сущность уже есть в деле.
9. OSINTchart не установлен/не запущен.
10. OSINTchart недоступен или его схема несовместима.
11. Недостаточно места на диске.
12. Chrome перезапустился во время захвата.
13. Ошибка импорта/экспорта, сохранена возможность повторить.

Любая ошибка должна быть понятной, с реальной причиной и действием пользователя. Не показывать «сохранено», пока не завершена проверка.

## 23. Реальные сценарии приёмки (критерии DONE)

### AC-01: выбор папки

Given пользователь выбрал `D:\Investigations\TraceVault`, When сохраняет три разные страницы, Then в правильной папке дела появляются три автономных HTML, индекс фиксирует их, Downloads не содержит случайных копий, повторный выбор папки не требуется до тех пор, пока браузер сохраняет выданный доступ.

### AC-02: устойчивость папки

Given доступ отозван после перезапуска браузера, When пользователь пытается сохранить страницу, Then UI честно пишет `Нет доступа к рабочей папке`, предлагает снова разрешить доступ и **не сообщает об успешном сохранении**.

### AC-03: офлайн HTML

Given архив сохранён со стилями и изображениями, When интернет отключён и файл открыт в обычном Chrome без расширения, Then основной доступный на момент фиксации текст и встроенные ресурсы доступны без сетевой зависимости, а неполнота захвата перечислена в журнале.

### AC-04: временные метки

Given страница сохранялась 4 секунды, When открыт список доказательств, Then видны как минимум `начало захвата`, `конец захвата`, `запись файла` с точной датой, временем, миллисекундами и UTC-зоной; различие между ними не скрыто.

### AC-05: выделение и выключение

Given выделение сохранено, When пользователь выключает `Показывать аннотации`, Then highlight сразу исчезает без изменения текста сайта; When включает обратно, Then возвращается на правильный фрагмент; When перезапускает браузер и открывает страницу, Then фрагмент восстанавливается, если однозначно найден.

### AC-06: изменённая страница

Given текст удалён из сайта, When пользователь повторно посещает URL, Then аннотация остаётся в хранилище, отображается как orphaned и связана с прежним зафиксированным архивом, но **не** подсвечивает случайное другое место.

### AC-07: Entity → первоисточник

Given пользователь выделил имя на странице и создал Person draft, When открывает его карточку, Then доступны исходная цитата, URL, точное время, `capture_id`, путь к сохранённому HTML и SHA-256 файла. При переключении версии страницы Evidence Reference остаётся на исходной версии.

### AC-08: OSINTchart экспорт

Given три Entity с общим Capture и пять Evidence References, When пользователь экспортирует пакет, Then JSON валиден по версии схемы, содержит три Entity, один общий источник фиксации и пять ссылок, пути относительны. Повторный импорт не создаёт дубли.

### AC-09: защита оригинала

Given PNG и HTML сохранены и захешированы, When пользователь редактирует заметку и цвет выделения, Then SHA-256 обоих первичных файлов остаётся неизменным.

### AC-10: прерывание

Given Chrome закрыт во время записи, When он запускается заново, Then нет фиктивных `completed`, неполные операции обнаружены и управляемо восстанавливаются/помечаются ошибкой.

### AC-11: поддержка двух тем и HiDPI

Given Windows 11, светлая/тёмная тема, масштаб 100/125/150/200%, When пользователь меняет размер Chrome Side Panel, Then отсутствуют обрезанные подписи кнопок, белые углы под скруглениями, нечитаемые пиксельные глифы, наложения и неправильная вертикальная прокрутка.

### AC-12: большие ресурсы и версионирование

Given пользователь сохраняет URL дважды, When сравнивает захваты, Then видит два capture ID, две даты и две независимые файловые записи; совпадение SHA, если оно есть, не уничтожает историю событий.

## 24. Матрица тестирования

### 24.1 Виды сайтов

Статический блог; Wikipedia-подобная страница; длинная статья; сайт с CSS background images; SPA с client-side routing; динамически раскрытый текст; страница с embedded SVG; responsive layout; iframe; shadow DOM; lazy loading; PDF-viewer; форма с паролем; закрытая Chrome page; сайт с большим количеством ресурсов; сайт с контентом на кириллице, арабском и emoji. Тестировать без попыток обойти защиту/авторизацию.

Schema validation, Unicode, UTC DST переходы, UUID uniqueness, перезапуск браузера, пропажа диска, снятие разрешений, частичные записи, несовместимость схемы, битый архив, неверный hash, дубли Entity, одинаковые цитаты, отсутствующие iframe, отсутствие доступа в сеть, перенос Workspace на другую машину, восстановление индекса.

### 24.3 Интеграционные

Playwright (Chromium extension persistent context) или эквивалент для E2E с реальным браузером, unit тесты нормализации и якорей, golden screenshots/визуальные регрессии, тесты хеширования на записанных байтах, mock native bridge. ## 25. План разработки по этапам

### Этап 0 — исследование и прототип

Подтвердить Chrome MV3 + File System Access permission persistence для целевой версии Chrome, проверить записываемую директорию из Side Panel, сделать proof-of-concept SingleFile-подобного захвата трёх сайтов и автономный HTML, определить лицензионную стратегию. Документировать найденные ограничения. Прототип не считается MVP.

### Этап 1 — рабочий MVP P0

Рабочая область/дела/выбранная папка, захват страницы как один HTML, видимый скриншот PNG, точные времена, SHA-256, список материалов, карточка доказательства, создание заметок и выделений, их toggle и сохранение, локальные Entity drafts с source refs, переносимый JSON-экспорт, восстановление после перезапуска. Финальные AC-01..AC-12, кроме обозначенных P1 деталей, должны проходить.

### Этап 2 — качество доказательств

Устойчивое архивирование сложных страниц, полные скриншоты, диагностика неполных ресурсов, диффы, текстовый индекс и OCR, улучшение экспортов, подписанные/связанные журналы и опциональная метка времени.

### Этап 3 — интеграция с OSINTchart

Надёжный импортер на стороне OSINTchart, mapping для кастомных Entity, preview конфликтов, идемпотентность, native companion для прямой передачи и обратного перехода к конкретному материалу. Интеграция не должна ломать версии существующих дел.

### Этап 4 — расширения

Видео, групповой захват, специализированные правила сайтов, шифрование рабочих областей, совместная работа, мощные отчёты и расширенный локальный поиск только по отдельному решению заказчика.

8. Документ совместимости с репозиторием OSINTchart; source mapping и тесты импортёра.
9. CHANGELOG и явный статус P0/P1/P2, без преувеличений выполненной работы.
10. Небольшой набор тестовых фиксаций из публичных безопасных сайтов без персональных данных.

## 27. Definition of Done

Задача считается завершённой не по красивому макету, а если исследователь может: выбрать одну директорию, создать дело, открыть сайт, сохранить автономный HTML, открыть его без сети, увидеть точную дату и время и SHA-256, выделить на сайте цитату, скрыть/восстановить выделение, создать Entity со ссылкой на конкретный первоисточник, перезапустить Chrome без потери дела и экспортировать переносимый пакет для OSINTchart. Все элементы должны работать, а не быть placeholder-функциями.

## 28. Продуктовые решения, которые должны остаться настраиваемыми

- Один общий Workspace с подпапками дел **или** одна выбранная папка на одно дело.
- Какие действия автоматически архивируют страницу при создании цитаты/Entity (по умолчанию без скрытого автоматического захвата).
- Горячие клавиши.
- Цвета и видимость аннотаций.
- Показывать Source Entity на графе OSINTchart или только Evidence Reference (по умолчанию Evidence Reference без лишнего графового узла).
- Фильтры чувствительных доменов.
- Дополнительная доверенная метка времени и шифрование после MVP.
